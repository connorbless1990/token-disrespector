# The DSH A/B — design (published before running, per the mission brief §4)

**Question:** how much does request-side context compression (tds) actually speed up, and
stabilize, a DSH agent session on this shared local 27B, and at what quality cost?

Published prediction to score against (2026-09-25): cold-cache turns ~30–45% faster
(≈1.4–1.8×); warm-cache turns a few–20% faster (delta-bound); plus KV-footprint shrinkage =
stability under concurrent load (the exact 2026-09-25 failure: a copilot session 502'd when
the shared model died under dual-session load).

---

## 1. Arms (one at a time — NEVER concurrent)

| Arm | Provider route | Proxy | MCP row | Purpose |
|---|---|---|---|---|
| **T** — treatment | `incoai-tds` → `http://127.0.0.1:8788/v1` | running, `--ccr on` | `mcp__ctxroom__*` present | the full tds effect |
| **C** — control | `incoai` → `http://127.0.0.1:8000/v1` (direct) | irrelevant (not in path) | absent | the baseline |
| **P** — passthrough (optional) | `incoai-tds` | running, `--ccr off` | `mcp__ctxroom__*` present | isolates the proxy's own overhead (no lossy compression; stats must show zero transforms) |

Switching arms = one line in `~/.dsh/settings.yaml` (`agent-default-model.provider`),
hot-reloaded; the runner script writes it, waits 1 s, and restores on exit. The two routes
differ only in `baseURL`; model id, wire (`openai-completions` under `/v1`), key, and
everything else are identical across arms.

**Known asymmetry, published up front:** arm T carries two extra tool definitions
(`mcp__ctxroom__ctxroom_retrieve`, `mcp__ctxroom__ctxroom_stats`) in every request —
measured from `request/header` events and reported as part of T's overhead. That is an
inherent part of the tds setup (the agent must be able to fetch originals), not a bug.

## 2. Common A/B profile (symmetric in all arms)

Overlay applied via `dsh --profile headless --patch <arm.yml>`:

- `compaction-basic` → `config: { auto: false }` in **all** arms. Rationale (seam map §3):
  at the 262,144-token window the trigger sits at ~209,715 tokens, above the workload, so
  it would never fire — but the summarization call is an extra model request that would
  pollute per-turn timing, and a trigger *would* bust tds's frozen-prefix byte-identity.
  Disabled symmetrically to keep the A/B about compression, not compaction.
- `session-persistence-jsonl` → `config: { root: <~/.dsh/sessions>, compression: 'none' }`
  in **all** arms: plain JSONL (no multi-frame zstd) so the measurement parser is trivial
  and identical for both arms.
- Arm T/P add the `mcp-ctxroom` insert row (mcp-client, stdio, `node packages/mcp/src/index.ts`).
- `DSH_TELEMETRY_DISABLED=1` on every experiment process (shipped OTel is FEEDBACK_ONLY, but
  the run must be clean); `CTXROOM_HOME=~/.ctxroom` default.

Workdir: a freshly generated seeded repo (below) — the DSH workspace root, so the agent's
file tools operate on it. `cwd` normalization (`/var` → `/private/var`) is handled in the
session lookup (realpath).

## 3. Workload — the seeded audit

A deterministic, seeded "service repo" (generated by `evals/dsh/gen-seed.ts`, mulberry32
seed, byte-identical for a stranger with nothing but Node), shaped on the E2/E4 corpus at
~0.4× scale so a full read peaks around **60–90k prompt tokens** (the brief's 50k+ target):

| file | shape (E2 family) | approx size |
|---|---|---|
| `logs/build.log` | build log, template-dominant (E4 burst first) | ~90 KB |
| `logs/api-dump.json` | indented JSON, ~120 records | ~32 KB |
| `logs/api-minified.json` | minified single-line JSON | ~40 KB |
| `src/{engine,compress,ccr,router}.ts` | 4 code files, line-numbered reads | ~80 KB total |
| `audit/grep-errors.txt` | ripgrep `path:line:content` dump | ~8 KB |
| `config/app.yaml` | large YAML config | ~8 KB |
| `notes/design-notes.md` | prose (EN) + CJK section | ~4 KB |
| `audit/diff.patch` | multi-file git diff | ~2 KB |

Total ≈ 260 KB ≈ **65–70k tokens** when all files are read — inside the 262k window with
compaction off, above every compression threshold, and a realistic audit shape (logs + JSON
dump + code + grep + config + prose + diff).

**The task** (fixed text, `evals/dsh/task.txt`) is a code-audit prompt: inspect the repo,
read the listed artifacts in full, then answer a **15-question factual battery** in a fixed
structured format (one answer per line, `Q<n>: <answer>`). The battery (adapted from E2's
20-question set) spans every shape: error-burst identity, exact counts (ERROR/WARN/INFO
lines, 5xx records, config keys), distinctive-token presence, a deep-line quote, first/last
record fields, CJK content, diff membership.

**Ground truth is computed from the generator, not mined from text**: `gen-seed.ts` also
emits `ground-truth.json` (each answer as a deterministic function of the generated data).
Scoring per arm: (1) **accuracy** vs ground truth, (2) **agreement** T-vs-C per question.
Quality gate (brief §4): ≥95% agreement and no question where T is right and C is wrong is
expected *by construction*; **any** disagreement is a setup failure → fix retention
(compressors) or narrow scope via engine config (`minInputWords`, `protectedPatterns`,
`maxBlockChars` — all env/config-settable, no code) and re-run. Never fudge the scorer.

## 4. Measures

Per run, per model request (from the session JSONL, both arms):
- **wall** = `step/end.time − step/start.time`; **TTFT** = first stream-chunk `time`
  minus `request/header` `time` (fallback `step/start`).
- **promptTokens** = `usage.inputTokens + usage.cacheReadTokens` (the model's full prompt);
  **outputTokens**; **cacheHit** = `cacheReadTokens / promptTokens` (the KV-cache hit ratio).
- **retries** (`llm/retry` events) and stream `TIMEOUT`/502 occurrences.
- Total run wall time; step count.

Arm T/P additionally from the proxy stats JSONL (joined by request timestamp/path):
- `tokensBefore → tokensAfter` (the compression delta as the proxy saw the wire bytes),
  `transforms` (which compressor fired), proxy-side `ms` (E6 p99 < 50 ms budget check).

Per arm (≥2 runs each): mean/median step wall, mean/median TTFT, mean prompt tokens,
mean cacheHit, total time, retry count, battery accuracy + agreement table.
Verdict = T-vs-C deltas on step wall (cold vs warm split: steps with cacheHit ≥ 0.9
count as "warm") and TTFT, against the §3-published prediction; P-vs-C = pure proxy
overhead.

## 5. Stability probe (the 2026-09-25 failure mode)

During each arm run, a **concurrent agent session** loads the shared model — copilot
`1.0.88` (installed at `~/.nvm/versions/node/v24.16.0/bin/copilot`) with the E4 shape:
temp home, seeded repo, `-p "Read logs/build.log and tell me what went wrong"`, routed
**direct** at `:8000` (so the probe itself is arm-agnostic load; it exercises the *model*,
not the proxy). Success = the arm run completes (exit 0, no 502/`upstream unreachable`,
no `LLM_STREAM_IDLE_TIMEOUT` retries) **and** the load session finishes. Runs: T-with-load
(the critical test — does the smaller KV footprint survive) and C-with-load (does the
baseline survive; the 2026-09-25 event says "sometimes"). One load session per run, started
mid-run.

## 6. Run protocol & honesty rules

1. **Quiet windows only.** Before each run: `curl :8000/v1/models` (liveness) + one 5-token
   probe request (baseline TTFT + latency, recorded in the run manifest). The Mac mini
   serves the user; this MacBook-Air session (me) is also on the model — the experiment
   runs in quiet hours and my own turns are minimal meanwhile.
2. **Never concurrent arms.** Sequence: T1 → C1 → T2 → C2 (→ P1, optional), with the
   provider flip between runs. Arms in one arm run the stability probe.
3. **Dead model = recorded, not patched.** If a run dies (`502 upstream unreachable`,
   tunnel drop, idle timeout), the run is logged with its failure mode and the arm is
   re-run; dead runs stay in the manifest (they are data about the shared model).
4. **Every number re-runnable**: `evals/dsh/run-ab.mjs` drives the whole sequence;
   results land in `evals/dsh/results/<timestamp>/` (manifest, session JSONL copies,
   stats slices, computed tables). The report cites run ids, not vibes.
5. Model server note: it lives on the Mac mini, reached here through the user's
   `ssh -L 8000` tunnel — one extra hop on **both** arms equally; a dropped tunnel is a
   recorded run failure, re-run the arm.

## 7. Budget

Current measured rate on this shared model (E8, 2026-09-25 ~23:00): ~100 s/step, small
session ≈ 17 min. The audit workload (8–15 steps, growing to ~70k prompt) is estimated
**20–40 min per run** → 4 runs ≈ 2–3 h, + 2 loaded runs ≈ +1 h. Target: one quiet window
overnight. If the model is busy (probe TTFT ≫ baseline), defer — do not pollute.

## 8. Deliverable

`docs/dsh-measured-gains.md`: numbers table per arm (step wall, TTFT, tokens, cacheHit,
retries, battery agreement/accuracy, overhead p99, stability outcome) + verdict against
the published prediction + the compaction-interaction outcome (off in both arms; the
on-by-default collision documented qualitatively) + honest limitations (single shared
27B, tunnel hop, 2–3 runs/arm, one workload shape, late-night window).
